### 実装上の判断（仕様の解釈）

- **KEEP_BOUNDARY で固定するコーナー:** 再計算の単位（S のうち入力 UV で連続な部分島）の境界にあるコーナーをすべて固定します。境界には、選択境界、メッシュ外周、入力 UV の分断、REQUIRE / 保護シームが含まれます。内部コーナーは、境界を固定した LSCM で解き直し、無効なら Tutte 写像で解き直します。
- **三角形分割:** Blender 上では `mesh.loop_triangles` を取り込み、展開と重複判定に同じ三角形を使います。以前は独自の分割を使っていたため、凹んだ UV 四角形で Blender の分割との差による見逃しがありました（統合テストで検出し、修正済み）。
- **重複判定:** 向きが揃った島は、境界線分が交差しなければ単射とみなします。島同士は、境界の交差と内部点の包含で判定します。境界が接触している場合や共線で重なる場合は、三角形の交差面積による厳密判定に切り替えます。総当たり判定との一致は `tests/unit/test_overlap_detection.py` で確認しています。
- **余白:** 島同士、および島とタイル端の間に `gap_px / resolution` を確保します。配置探索では、障害物と可動島をそれぞれ余白の半分だけ膨張させます。
- **トポロジー問題の扱い（R-007 からの意図的な逸脱）:** 0.1.0 では非多様体・向き不整合のエッジや面積0の面があると停止していましたが、実際のモデル（3面以上が共有するエッジ・裏返った面・面積0の面を含む円柱群）で展開できませんでした。0.1.1 から既定を「分割して続行」（`TopologyPolicy.SPLIT`）に変えています。問題のあるエッジでは UV を必ず分割し、面積0の面は向き・退化・最大歪みの判定から外します。該当箇所は警告として報告し、メッシュは変更しません。仕様どおりの停止は設定「トポロジー問題: 停止」で選べます。
- **IMPROVE（全体）:** 正常な既存島は形状と位置を保ち、再展開した島だけを空き領域に置きます。空きが足りない場合は、既存島の向きを保ったまま全体を再配置します。正常な基準 UV より総合コストが悪くなる結果は採用せず、既存 UV を維持します。

## 5. 既知の制限と未達事項

1. **製品閾値が未確定:** 仕様 10章が求める歪み・時間・メモリ・品質の閾値は、上の測定だけでは確定できません。そのため T-308 は未合格の扱いです。
2. **対応環境:** Blender 4.5 LTS、Linux、macOS で未検証です。
3. **性能:** 島数が多い入力では、Python で書いた配置・検証のループが支配的になります（10 Object・計 1 万三角形で約 8 秒）。50 万三角形級は未測定で、実用的な速度は保証しません。
4. **Blender 標準展開の呼出し:** 作業用 Mesh を作るたびにモードを切り替えるため、1 回あたり約 0.2 秒かかります。局所探索はラウンド単位で一括評価して呼出し回数を減らしていますが、候補数の予算を増やすと時間はほぼ比例して増えます。
5. **境界固定と Blender 標準展開:** pin 付きで Blender の展開を実行した場合の挙動は検証していないため、境界固定と pin を含む Chart は常に内蔵 LSCM（または Tutte）で解きます。
6. **UI:** モーダル実行、GPU オーバーレイ、パネル表示は対話環境で自動試験していません（ヘッドレスでは非モーダル実行を使用）。
7. **対称性:** 対象は Object ローカルの軸平面に対する鏡映ペアだけです。1 つの部品が自分自身と鏡映対称になるケースは配置に使っていません。
8. **IMPROVE で配置のみが不正な場合:** 既存島の向きは保ちますが、相対位置は元の位置の並び順で近似するだけで、元の配置そのものは保ちません。
9. **リンク／ライブラリオーバーライドの扱い:** 実装済み（`is_editable` による判定）ですが、試験していません。
